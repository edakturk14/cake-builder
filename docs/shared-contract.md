# Shared implementation handoff

Source of truth: `src/shared/cake.ts`.

- `CakeState`: `exists`, `base` sponge/cheesecake, `flavor` vanilla/chocolate/red-velvet/lemon/classic, `layers` 1/2/3, nullable `occasion: OccasionId|null`, nullable `theme`, `toppings`, `toppers: TopperId[]` (up to two unique, in placement order), `customTopper: {request:string,assetId:string|null}|null`, `candles: {style: none/plain/number, number: string|null, count:number|null}`, exact-text `inscription`, `colors`, `topperStyles`, and `inscriptionStyle`.
- `src/shared/occasions.ts` exports `OCCASIONS` (`id`, `label`, `jevDescription`, `suggestions`), `OccasionId`, `OCCASION_IDS`, `OCCASION_BY_ID`, and storage-only `matchOccasion`. IDs: `birthday`, `wedding`, `anniversary`, `engagement`, `graduation`, `promotion`, `retirement`, `baby-shower`, `christening`, `housewarming`, `christmas`, `new-year`, `valentines-day`, `mothers-day`, `fathers-day`, `thank-you`, `just-because`. Setting an occasion is free and changes only its label, never adds implied decorations. Old saved labels migrate by supported ID/label match; unknown old labels become null without discarding the cake.
- `CandleState`, `CandlePatch`, `DEFAULT_PLAIN_CANDLE_COUNT=5`, and `PLAIN_CANDLE_COUNTS=[1..12]` are exported from `cake.ts`. Candle patches merge partially. Plain has count 1–12 and number null; numeral has number 0–999 and count null; none clears both. Switching to plain defaults to five; editing an existing plain set preserves an omitted count. Switching to numeral requires a number; number-only edits preserve existing numeral style. Explicit style changes clear incompatible fields. Plain sets cost $3 at every count; numeral sets cost $5, not per digit. Old saved plain sets migrate to five, other old styles get count null. Spec pills distinguish `3 candles` and `3 candle (numeral)`.
- Themes: `mario`, `formula-one`, `spain-world-cup`, `tennis`, `jensen-huang`.
- Toppings: `strawberries`, `raspberries`, `ganache`, `caramel`, `gold-stars`.
- `CakePatch`: optional state fields plus `addToppings`, `removeToppings`, `addToppers`, `removeToppers`, `notes`. Omitted fields preserve confirmed values; `null` removes nullable items; `toppings` and `toppers` replace their full lists.
- `src/shared/toppers.ts` exports readonly `TOPPER_CATALOG` (41 `{id,label,jevDescription,priceCents:1000}` entries), `TopperId`, `TOPPER_IDS`, and `TOPPER_BY_ID`. Prepared topper price line IDs are `topper:<id>`. A third unique topper rejects the entire patch with note `Up to two toppers in this demo`. Legacy basket `topper:'princess'|null` migrates to `toppers`; current state and patch no longer accept `topper`.
- `applyCakePatch(current, patch)` returns **`{state, notes}`**. Runtime validation bounds all options and exact text. Removal wins over an add of the same topping in one turn.
- `EMPTY_CAKE` is nonexistent chocolate sponge, one layer.
- `estimateCake(cake)` returns `{totalCents,lines:[{id,label,amountCents}],requiresQuote,quoteItems}`. All price math uses integer cents. `formatMoney` formats sample USD.
- `createBasketItem` deep-clones and freezes design, price lines and quote requests. `parseBasket` validates storage, restores bounded designs, and recalculates estimates. `cakeReducer` stores immutable history snapshots.
- `src/shared/fixtures.ts` has 14 opt-in local examples and six demo turns (the initial four, Ada correction, princess removal). Replay supports local Undo through the same immutable reducer. These are not live interpretation or model timing evidence.
- `src/shared/discoverability.ts` derives `getAskOptions()` from shared catalogs/prices and `getCakeSuggestions(cake)` from confirmed state. Occasions appear first, themed kits are “Designs you can describe,” and empty suggestions start with “A birthday cake.” Selected occasions prefer unsatisfied contextual suggestions without applying them automatically. Suggested strings always use the real typed-command path. Shared layer and candle options are exported from `cake.ts`.
- `src/shared/appearance.ts` exports 17-color `PALETTE`, `PaletteId`, `PALETTE_IDS`, `PALETTE_BY_ID`, `COLOR_TARGETS`, `SIZE_OPTIONS`, `POSITION_OPTIONS`, `WRITING_FONT_OPTIONS`, `WRITING_CASE_OPTIONS`, `WRITING_PLACEMENT_OPTIONS`, defaults, `paletteHex(id,fallback)`, and `getTopperStyle(styles,id)`.
- `CakeColors`: `{frosting,filling,inscription,accents:PaletteId|null}`. Null means artwork default. `TopperStyle`: `{size:small|medium|large,position:auto|left|center|right,tint:PaletteId|null}`. `InscriptionStyle`: `{font:script|print,letterCase:as-written|upper,size:small|medium|large,placement:front|center}`. State containers are normalized; patches merge nested optional fields. Per-topper null clears its style. Removing a topper deletes its style.
- Appearance is free. `customTopper.request` remains exact text and quoted even with an image. Changing to a different normalized request clears an omitted asset ID. Asset IDs are 1–128 alphanumeric, underscore or hyphen characters, never URLs or paths.
- `normalizeCustomRequest(request)` makes a NFKC, trimmed, whitespace-collapsed lowercase cache/match key without changing stored text.
- `cakeReducer` action `{type:'assetReady',request,assetId}` hydrates the current custom request and matching history without adding an Undo step; a no-longer-current request is ignored. `fulfillBasketAsset(items,request,assetId)` is the sole allowed post-save design update: fill only a null image ID for a matching request, preserving every other field and all prior image IDs.
- `useCakeDesigner({onAssetReady})` emits every completed asset event, even if the builder changed or reset. App uses that event to fulfill saved pending thumbnails. `readyAssets:ReadonlyMap<string,string>` uses normalized request keys. Image work does not disable Add to basket; App shows `imagePending`/`imageError` quietly and a separate image-generation timing column.

Ownership: shared contract/scaffold/App/integration CSS/tests/README belong to builder; `components/BuilderPage.tsx`, `components/CakeScene.tsx`, `styles/builder.css`, and artwork belong to visual; server/hooks/queue/interpretation contracts belong to voice.
